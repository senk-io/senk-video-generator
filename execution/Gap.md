# 偏差模型

## 制度冻结信息

```text
Freeze ID: IF-0003
Constitution: AI Native Engineering Constitution
Chapter: Gap Model
Status: FROZEN
Source Conversation: 6a6ecde3-0aa4-83ee-a53c-7c707fbf57f2
Source Turn: 598b5375-ccb8-4d21-953e-823e200d8770
Depends On: IF-0001 Authority Model
Depends On: IF-0002 Expectation Model
```

本章定义 AI 原生工程中的偏差模型。偏差不是通过、失败、错误或策略，而是观察现实与冻结预期之间正式存在的差异事实。

> 验证发现现实；偏差驱动系统演化。

本章中的“必须”“不得”和“只能”均为规范性要求。诊断、策略和学习必须以本章定义的偏差事实为输入，不得绕过偏差直接解释观察。

## G-01 偏差是一等事实

偏差不是附属于验证报告的临时结果，而是必须独立保存、版本关联、追踪和审计的一等事实。

传统流程把信息压缩成：

```text
Expectation
  -> Execution
  -> PASS | FAIL
```

这种结果无法说明差异在哪里，也不能支持后续诊断和学习。受治理的推导必须是：

```text
Expectation
  -> Observation
  -> Gap
```

每个偏差必须保留其所引用的预期版本、观察证据和产生时间，不得在汇总为通过或失败后被丢弃。

## G-02 偏差不等于错误或失败

系统必须区分：

- **偏差**：现实与预期之间存在差异。
- **错误**：系统不变量被破坏。
- **失败**：当前策略无法继续，系统因此停止。

例如，候选资产未经接受就进入时间线，属于不变量错误，不是创作偏差。

三者可能形成以下关系：

```text
Gap
  -> may cause Error
  -> may cause Failure
```

但不能据此把任何偏差自动称为错误，也不能从一次失败反向虚构某个偏差。

## G-03 偏差只能建立在观察之上

偏差必须来自可追踪观察，不得建立在猜测、动机推断或对模型内部状态的想象之上。

非法表述：

```text
AI 应该理解错了
```

合法事实：

```text
Expected: Left
Observed: Right
```

只有预期值和观察值都可定位时，偏差才能正式成立。

## G-04 每个偏差只属于一项预期

偏差不得脱离预期独立存在。每个偏差必须引用且只引用一项冻结预期。

```text
Gap -> Expectation-41
```

若一次观察同时偏离多项预期，必须为每项预期分别建立偏差事实，不能创建一个含义模糊的综合失败。

## G-05 一次观察可以产生多个偏差

一个观察现实可以同时与多个预期不同。例如：

```text
Observation: Warm, Fast, Handheld
Expectation: Cool, Slow, Dolly
```

系统必须分别记录色彩、速度和镜头运动三个偏差，而不是压缩成一个 `FAIL`。

每个偏差必须独立编号、独立追踪，并拥有独立的后续诊断关系。

## G-06 偏差必须分类

每个偏差必须属于明确类别，不能只有通过或失败标签。

### 结构偏差

对象、关系或结构不符合预期，例如错误角色、错误场景或错误时间线。

### 行为偏差

动作或时序行为不符合预期，例如相机、运动或时长差异。

### 语义偏差

表达含义不符合预期，例如情绪、叙事或意图差异。

### 创意偏差

观众感受、审美或影响力与创意预期存在差异。创意偏差不得自动裁决。

### 技术偏差

技术属性不符合预期，例如分辨率、编码、帧率或字幕问题。

分类只描述差异的性质，不决定下一步行动。

## G-07 偏差必须拥有严重程度

每个偏差必须声明严重程度：

```text
Critical
Major
Minor
Informational
```

严重程度是对现实影响的描述，不是策略。例如错误人物可以是严重偏差，相机速度轻微超出范围可以是轻微偏差。

严重程度本身不得自动触发重试、拒绝或人工评审；行动仍由策略决定。

## G-08 偏差不得决定行动

偏差回答现实与预期差在哪里，策略回答应采取什么行动。

偏差不得自行声明：

```text
Retry
Repair
Human Review
Accept
Reject
```

将行动写入偏差事实会使偏差越过现实描述边界并获得策略权威。

## G-09 偏差不可变

偏差一旦由特定预期版本和观察证据正式产生，就不得修改、覆盖或重新解释为另一个差异。

新的观察必须产生新的偏差事实；后续解释必须追加独立诊断：

```text
Gap
  -> Diagnosis-1
  -> Diagnosis-2
```

所谓版本化是记录偏差所依赖的预期与观察版本，以及新旧偏差之间的关联，不是修改既有偏差内容。

## G-10 偏差先于诊断

诊断不得直接解释观察，必须引用已经成立的偏差。

非法推导：

```text
Observation
  -> Diagnosis
```

合法推导：

```text
Observation
  -> Gap
  -> Diagnosis
```

否则诊断会在没有预期边界的情况下自行解释现实。

## G-11 偏差可以被接受

不是所有偏差都必须消除。软预期和创意预期可以容纳偏差。

偏差本身只陈述现实，不包含价值判断。接受、拒绝或修复由策略或拥有相应权威的裁决者决定。

```text
Gap -> Policy -> Accept | Reject | Repair
```

“可接受”不能用于反向删除偏差；被接受的偏差仍然是历史事实。

## G-12 偏差创造学习机会

学习不能只学习通过或失败标签，而必须学习具体偏差及其上下文。

```text
Repeated Gap
  -> Pattern
  -> Knowledge
  -> Institution
```

只有可追踪的重复偏差才能支持模式识别。没有偏差事实的成功或失败，不得直接进入知识库。

## G-13 偏差不得自行升级

单个偏差不能自动变成知识或制度，必须经过：

```text
Gap
  -> Pattern Review
  -> Knowledge Approval
  -> Institution Freeze
```

缺少模式评审、知识批准或制度冻结时，经验只能保持为个案，不得污染基础层。

## G-14 偏差是诊断的唯一合法输入

诊断只能解释偏差，不能直接解释观察，也不能绕过预期。

```text
Expectation
  -> Observation
  -> Gap
  -> Diagnosis
```

这是诊断成立的唯一合法推导链。任何诊断都必须引用一个具体、不可变的偏差事实。

## 偏差成立条件

偏差只有同时满足以下条件才能成为正式事实：

- 引用一项冻结预期及其版本；
- 引用可追踪观察及其证据；
- 明确表达预期值与观察值的差异；
- 只归属于一项预期；
- 拥有独立标识；
- 已归入一个偏差类别；
- 已声明严重程度；
- 不包含诊断解释或策略行动。

## 非法状态总表

以下情况一律非法：

- 用 `PASS` 或 `FAIL` 代替具体偏差事实；
- 根据猜测而不是观察建立偏差；
- 一个偏差同时归属于多项预期；
- 把多个差异压缩成一个综合失败；
- 把偏差、错误和失败混为同一概念；
- 在偏差中写入重试、修复、接受或拒绝行动；
- 修改、覆盖或删除已经成立的偏差；
- 诊断直接解释观察而不引用偏差；
- 因为偏差被接受就删除其历史；
- 让单个偏差自动升级为知识或制度。

发现非法状态时，系统必须失败关闭并保存证据。

## 系统演化主轴

```text
Expectation
  -> Observation
  -> Gap
  -> Diagnosis
  -> Policy
  -> Learning
```

这不是可随意调整的工作流，而是 AI 原生工程唯一合法的演化路径。

## 本章边界

本章定义偏差事实，不定义偏差原因。诊断如何保持解释与事实分离、如何容纳多个竞争解释以及如何管理诊断置信度，已由 `IF-0004` 建立，见 [`Diagnosis.md`](./Diagnosis.md)。
