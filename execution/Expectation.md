# 预期模型

## 制度冻结信息

```text
Freeze ID: IF-0002
Constitution: AI Native Engineering Constitution
Chapter: Expectation Model
Status: FROZEN
Source Conversation: 6a6ecde3-0aa4-83ee-a53c-7c707fbf57f2
Source Turn: 00e02a54-24ec-461c-8e9a-02dfa8f0afe1
Depends On: IF-0001 Authority Model
```

本章定义 AI 原生工程中的预期模型。预期不是提示词、需求描述或生成结果，而是拥有正式生命周期的成功权威。

> 工程中的成功，不由结果定义，而由预期定义。

本章中的“必须”“不得”和“只能”均为规范性要求。执行、验证、诊断和策略不得改变已经冻结的预期。

## E-01 预期定义成功

AI 只能产生现实，不能定义成功。成功必须在执行之前已经存在。

没有正式预期时，系统只能事后观看结果并凭感觉判断：

```text
Generate
  -> Judge
```

受治理的执行必须遵循：

```text
Expectation
  -> Execution
  -> Verification
```

成功必须来自预期，不得来自观察结果、最终产物或执行者的自我评价。

## E-02 预期是权威对象

预期不是普通描述，而是正式权威对象，并拥有完整生命周期：

```text
Create
  -> Freeze
  -> Version
  -> Supersede
  -> Retire
```

只有获得预期权威的主体才能创建、冻结、修订、取代或退役预期。

预期一旦冻结，执行者不得自行修改。任何变化必须产生新版本，并由对应权威完成正式迁移。

## E-03 意图不等于预期

意图回答：

> 创作者想表达什么？

预期回答：

> 系统如何知道已经表达成功？

例如，“孤独”是意图，不是可以直接执行或验证的预期。它可能被细化为：

```yaml
camera:
  movement: slow
lighting:
  style: low_key
palette:
  saturation: low
environment:
  occupancy: empty
```

意图必须先转换为预期，不能直接进入执行。提示词也不能代替这一转换。

## E-04 预期必须可观察

每项预期必须映射到至少一个可观察对象，使系统能够比较预期与实际观察。

```yaml
expectation:
  camera: dolly_in
observation:
  camera: handheld
```

两者差异产生偏差。

“希望”“高级感”“有力量”等表达不能直接验证，必须继续细化，直到拥有可观察、可验证或可推导的对象。

无法观察、无法验证且无法推导的预期，不得进入执行。

## E-05 预期固定分为三类

### 硬预期

硬预期必须满足，例如：

```text
Duration
Aspect Ratio
Character Identity
Language
Scene
Safety
```

任何适用硬预期被违反，立即产生失败，不得由软评分抵消。

### 软预期

软预期允许受控偏差，例如：

```text
Camera Smoothness
Color Preference
Music Style
Composition
```

软预期可以产生偏差和评分，但必须声明可接受范围。

### 创意预期

创意预期涉及：

```text
Audience Feeling
Artistic Value
Narrative Impact
```

创意预期不得自动通过，也不得自动失败，只能进入创意评审。

## E-06 不完整预期不得静默执行

发现预期缺失时，系统必须先分类，再决定是否能够继续。

### A 类：阻断执行

例如缺少主体、目标或输出类型。系统必须停止，不能应用默认值绕过。

### B 类：可恢复

例如缺少相机或音乐设定。系统可以询问，也可以使用已经存在且获授权的默认策略。

没有正式默认策略时，不得把模型偏好伪装成默认值。

### C 类：创意未知

例如“电影感”“高级感”“有力量”。AI 不得自行解释，必须继续预期细化。

## E-07 预期细化不是执行

预期必须在执行开始前完成细化。系统禁止在生成过程中一边执行、一边猜测成功含义。

执行者不得承担预期细化权威。执行发现预期不足时，应返回预期阶段，而不是自行补写或降低预期。

## E-08 预期版本控制下游有效性

预期版本发生变化时，系统必须重新计算所有下游对象的有效性。

```text
Expectation v3
  -> Shot
  -> Subtitle
  -> Voice
  -> Timeline
```

预期升级后，受影响对象必须重新验证。不得在没有验证的情况下静默保持有效。

版本变化不必无差别失效整个项目，但必须根据依赖关系计算影响范围，并保留失效证据。

## E-09 预期不得从观察反向推导

观察结果不得修改预期。

例如，模型无法生成缓慢推进镜头时，系统不得把预期静默改成静止镜头。这是在迁就模型，不是工程验证。

```text
Observation -/-> Expectation
```

预期只能由拥有对应权威的主体定义和修订，不能由模型能力、生成现实或最终结果反向产生。

## E-10 每项预期必须回答七个问题

任何预期在冻结前都必须回答：

1. 谁定义了它？
2. 为什么需要它？
3. 成功具体意味着什么？
4. 什么对象可以被观察？
5. 什么证据能够证明它？
6. 什么程度的偏差可以接受？
7. 谁拥有这项预期？

任何一项无法回答，预期都不得冻结。

## E-11 预期创建验证范围

验证不能自行决定检查什么。每个检查项都必须由冻结预期派生。

如果预期没有声明灯光要求，验证器不得自行增加灯光检查并据此阻断结果；否则验证器已经越过验证权威，开始创造新的成功标准。

```text
Expectation
  -> Verification Scope
  -> Verification
```

验证可以报告无法观察或证据不足，但不能补造预期。

## E-12 预期是唯一的成功定义

整个系统唯一的成功权威是冻结预期，不是 AI、提示词、模型、提供者、观察结果或导出文件。

预期依次定义：

```text
Success
  -> Verification Scope
  -> Gap Space
  -> Diagnosis Boundary
  -> Policy Space
```

因此，AI 原生工程真正的起点是预期，而不是执行。

## 冻结准入条件

预期只有同时满足以下条件才能进入 `Freeze`：

- 拥有明确的预期权威和所有者；
- 已说明目的与成功含义；
- 已分类为硬预期、软预期或创意预期；
- 已映射到可观察对象；
- 已定义证据来源；
- 已声明可接受偏差；
- 已创建验证范围；
- 不依赖执行结果反向成立。

## 非法状态总表

以下情况一律非法：

- 没有冻结预期就开始正式执行；
- 把意图、提示词、模型输出或导出物直接当作预期；
- 执行者在执行过程中细化或修改预期；
- 无法观察的预期直接进入执行；
- 对创意预期自动作出通过或失败裁决；
- 缺失预期时静默使用未经授权的默认值；
- 预期版本变化后让下游对象静默保持有效；
- 根据模型能力或观察结果反向降低预期；
- 验证器检查预期范围之外的标准；
- 七个冻结问题未回答完整却宣布预期已冻结。

发现非法状态时，系统必须失败关闭并保存证据。

## 本章边界

本章定义预期如何成为成功权威，不定义偏差的正式语义、分类和生命周期。偏差模型必须由后续独立制度冻结建立。
