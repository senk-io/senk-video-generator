# 验证模型

本文件的验证范围必须由 [`Expectation.md`](./Expectation.md) 中已冻结的预期派生。验证器无权创建新的成功标准，也不得检查预期范围以外的条件并据此阻断结果。

本文件尚未获得独立制度冻结。根据 `IF-0003`，验证的合法产物是可追踪观察，以及观察与预期不同时形成的 [`Gap`](./Gap.md)。验证器不得直接产生 `PASS` 或 `FAIL`。

## 验证目标

验证不回答“艺术是否存在唯一正确答案”，而回答结果是否忠实执行了已声明的创作意图与工程约束。

## 三层验证

### 硬检查

时长、画幅、编码、指定角色、必需场景、字幕安全区、必需台词和方向等确定性约束。任何适用硬预期与观察不同，必须产生对应偏差；后续裁决不属于验证权威。

### 软评分

节奏、色调、稳定性、主体位置、音乐克制度等程度型目标。每项必须记录评分尺度、阈值、置信度和证据，不允许只有无依据的总分。

### 创意评审

孤独感、希望感、电影感、观看欲望等主观目标由人类或被明确授权的评审者裁决。自动模型只能提供观察和建议。

## 下游裁决状态

以下标签不是验证器的直接输出，只能由后续策略或相应裁决权威产生：

- `PASS`：相应权威裁决适用偏差不阻断接受。
- `FAIL`：相应权威裁决当前策略不能继续。
- `REQUIRES_REVIEW`：需要创意或业务裁决。
- `UNKNOWN`：缺少观察、证据或裁决能力。

验证器只报告观察和偏差，不得自行分配这些裁决状态。

## 质量门

```text
Technical Gate
  -> Semantic Gate
  -> Continuity Gate
  -> Selection Gate
  -> Timeline Gate
  -> Export Gate
  -> Publication Gate
```

后一道质量门不能替代前一道质量门，也不能通过最终播放正常反推素材曾通过语义或选择审查。

## 最小证据要求

每次验证至少保存验证对象及版本、冻结预期、观察值、观察证据、验证者和发生时间。存在差异时，必须建立独立偏差事实，不能只保存汇总标签。

验证负责产生观察并建立偏差，不负责决定重试、降级、接受、拒绝或发布。后续动作由策略引擎或相应裁决权威决定。
