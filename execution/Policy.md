# 策略模型

## 制度冻结信息

```text
Freeze ID: IF-0005
Constitution: AI Native Engineering Constitution
Chapter: Policy Model
Status: FROZEN
Source Conversation: 6a6ecde3-0aa4-83ee-a53c-7c707fbf57f2
Source Turn: 7b5f1dcd-ce0d-4a70-b9b7-c393ce2335a9
Depends On: IF-0001 Authority Model
Depends On: IF-0002 Expectation Model
Depends On: IF-0003 Gap Model
Depends On: IF-0004 Diagnosis Model
```

本章定义 AI 原生工程中的策略模型。策略不是工作流、自动化或 AI 的临时判断，而是唯一有资格授权未来执行的制度对象。

> 执行产生现实；现实暴露偏差；偏差驱动诊断；诊断约束策略；策略授权下一次执行。

本章中的“必须”“不得”和“只能”均为规范性要求。任何未来行动都必须经过被选择且获得授权的策略。

## P-01 策略是未来执行的唯一合法控制者

现实已经发生、偏差已经成立、诊断已经形成以后，只有策略有权决定下一步。

以下推导非法：

```text
Gap -> Retry
Diagnosis -> Repair
Verification -> Skip
```

唯一合法路径是：

```text
Gap
  -> Diagnosis
  -> Policy
  -> Execution
```

验证器、偏差、诊断、执行器和模型都不得绕过策略直接触发未来执行。

## P-02 策略永远不改变历史

策略只能改变未来，不得修改已经发生的现实、观察、偏差、诊断或裁决历史。

```text
Policy -/-> Modify Gap
Policy -/-> Rewrite Diagnosis
```

策略可以决定重新执行或收集新证据，但新结果必须形成新的现实、观察、偏差和诊断，不能覆盖上一轮记录。

## P-03 策略拥有行动空间

工程中的所有后续行动都属于策略权威。标准行动空间包括：

### 重试

使用被授权的执行契约重新执行。

### 修复

对预期、提示词、约束或参考对象创建获授权的新版本。已经冻结的预期不得原地修改。

### 重新规划

重新规划故事、镜头或时间线等受影响对象。

### 替换提供者

为下一次执行选择不同生成提供者。

### 升级

请求更高权威作出决策。

### 人工评审

将需要人工裁决的事项交给被授权的人。

### 终止

结束当前执行闭环，不再产生下一次执行。

执行器不得自行创造任何行动，也不得把内部重试伪装成同一次执行。

## P-04 策略必须被选择，不能被猜测

诊断不会自动推出唯一策略。例如“提供者能力限制”既可能对应重试，也可能对应替换提供者。

策略必须经过明确选择，并记录选择依据。模型推断可以提供候选策略，但不能代替正式策略选择。

```text
Diagnosis != Policy Selection
```

## P-05 策略依赖权威，而不是能力

系统知道如何执行某项行动，不代表它有权执行。

例如，AI 即使能够修复提示词，没有提示词权威也不得执行修复。

每项策略必须同时满足：

```text
Policy Selected
AND
Authority Granted
```

缺少任意一项，系统必须失败关闭。

## P-06 同一上下文中的策略必须确定

在现实、偏差、诊断集合、策略版本和授权上下文完全相同时，策略必须产生相同决策。

同一策略版本不得随机选择行动。需要随机实验或 A/B 测试时，实验分配本身必须成为显式、可复现的策略上下文。

策略版本可以变化；不同版本可以产生不同决策，但必须保留版本边界和选择证据。

## P-07 策略拥有执行预算

任何未来执行都必须由策略声明预算，例如：

```text
Retry <= 3
Repair <= 2
Escalate <= 1
```

预算属于策略，不属于执行器。执行器不得自行增加次数、成本、时间或资源上限。

预算耗尽时必须回到策略权威，进入升级、终止或其他正式行动，不能静默继续。

## P-08 策略可以降级，但不能隐藏

策略可以把创意偏差交给人工评审，也可以在拥有相应权威时接受轻微偏差。

策略不得修改、删除或隐藏被接受的偏差。

```text
Accept Gap != Remove Gap
```

降级只改变未来处理方式，不改变偏差作为历史事实的存在。

## P-09 策略创建执行意图

执行器不得自行决定为什么执行。每次执行都必须引用明确的策略意图。

合法示例：

```text
Action: Retry
Purpose: Provider Timeout
```

非法示例：

```text
Action: Retry
Purpose: Maybe Better
```

执行意图必须能够追溯到偏差、诊断、策略选择和授权。

## P-10 策略不得评价自己

策略不能宣称自己是好策略或已经有效。

策略只能授权下一次执行。下一次执行产生新的现实和观察，再由独立验证建立新的偏差。

```text
Policy
  -> Next Execution
  -> New Observation
  -> New Gap
```

策略效果必须通过后续闭环评估，不能自证。

## P-11 策略必须可替换

策略属于制度，不属于现实，因此允许版本演化、A/B 测试和受控实验。

任何策略变化都必须产生新版本，禁止静默修改。

历史执行必须始终能够回答当时使用了哪个策略版本，不能用当前策略重新解释过去决策。

## P-12 策略拥有行动责任

任何行动最终都必须回答：

1. 谁选择了这项策略？
2. 为什么选择它？
3. 它依据哪个偏差和哪些诊断？
4. 使用了哪个策略版本？
5. 依赖什么授权？

无法回答时，后续执行非法。

诊断不决定责任归属；行动责任由策略选择和授权事实承担。

## P-13 策略是推理与执行之间的唯一桥梁

偏差和诊断属于推理侧，执行会进入现实侧。策略是连接两者的唯一合法桥梁。

```text
Reasoning
  -> Policy
  -> Execution
```

任何推理、模型建议或 Agent 内部判断都不得直接驱动执行。

## P-14 策略结束上一轮并开启下一轮

策略不是闭环终点。它结束上一轮对偏差的处理决策，同时授权或终止下一轮执行。

选择重试、修复、重新规划、替换提供者、升级或人工评审会开启相应的下一阶段；选择终止则正式关闭当前闭环。

每一轮都必须拥有独立的策略决策和执行记录。

## 策略成立条件

策略只有同时满足以下条件才能授权未来执行：

- 引用具体偏差；
- 引用一个或多个当前诊断及其版本；
- 经过明确策略选择，而非自动猜测；
- 声明策略版本；
- 获得执行对应行动所需的权威；
- 声明执行意图；
- 声明适用行动和作用范围；
- 声明次数、成本、时间或资源预算；
- 保留诊断的不确定性；
- 不修改或隐藏任何历史事实；
- 能够追溯选择者、原因和授权。

## 非法状态总表

以下情况一律非法：

- 偏差、诊断或验证器直接触发执行；
- 策略修改历史现实、观察、偏差或诊断；
- 执行器自行决定重试、修复或其他行动；
- 根据诊断自动猜测唯一策略；
- 有能力但没有授权时继续执行；
- 同一策略版本和相同上下文产生随机决策；
- 执行器自行增加预算；
- 接受偏差后删除或隐藏偏差；
- 执行缺少可追踪的策略意图；
- 策略评价或验证自身效果；
- 静默修改策略而不建立新版本；
- 行动无法说明选择者、原因、诊断和策略版本；
- 推理或模型建议绕过策略直接驱动执行。

发现非法状态时，系统必须失败关闭并保存证据。

## 完整闭环

```text
Reality
  -> Expectation
  -> Execution
  -> Observation
  -> Gap
  -> Diagnosis
  -> Policy
  -> Next Execution
```

这一闭环的核心定义是：

> 执行产生现实；现实暴露偏差；偏差驱动诊断；诊断约束策略；策略授权下一次执行。

## 本章边界

本章定义谁可以改变未来执行，不定义系统为什么相信现实、偏差、诊断和策略证据。正式证据的资格、充分性、版本和审计边界已由 `IF-0006` 建立，见 [`../foundation/05_Evidence.md`](../foundation/05_Evidence.md)。
