# 证据模型

## 制度冻结信息

```text
Freeze ID: IF-0006
Constitution: AI Native Engineering Constitution
Chapter: Evidence Model
Status: FROZEN
Source Conversation: 6a6ecde3-0aa4-83ee-a53c-7c707fbf57f2
Source Turn: 32343e8c-8e75-4578-a5a8-19d33e984efd
Depends On: IF-0001 Authority Model
Depends On: IF-0002 Expectation Model
Depends On: IF-0003 Gap Model
Depends On: IF-0004 Diagnosis Model
Depends On: IF-0005 Policy Model
```

本章定义 AI 原生工程中的证据模型。工程信任不来自 AI、人、模型或权威主体本身，而来自可定位、不可变和可审计的证据。

> 任何正式结论都必须拥有证据；没有证据时，系统只能保持未知。

本章中的“必须”“不得”和“只能”均为规范性要求。证据记录过去，不解释原因、不授予权威，也不决定未来行动。

## EV-01 证据先于信任

AI 会犯错，人会犯错，拥有权威的主体也会犯错。系统不能因为主体身份而相信一个结论，只能依据证据建立信任。

任何正式结论都必须引用证据。缺少证据时，合法状态只能是：

```text
UNKNOWN
```

主体声誉、模型置信度和人工确信都不能替代证据。

## EV-02 证据不可变

证据记录已经发生的现实，不得修改、覆盖或事后补写。

发现证据错误时，只能追加独立更正，并保留原始证据：

```text
Evidence
  -> Correction
```

更正必须引用原证据并说明错误和更正依据。原始历史不得消失。

## EV-03 证据不得解释自己

证据回答发生了什么，不回答为什么。

合法证据：

```text
Observed: Camera = Handheld
```

非法证据：

```text
Reason: Prompt Too Weak
```

原因属于诊断。把原因写入证据会让证据越过现实记录边界。

## EV-04 证据必须绑定版本

每项证据必须绑定所有适用版本，包括：

```text
Expectation Version
Execution Version
Provider Version
Policy Version
Asset Version
```

不适用的版本必须明确标记为不适用，不能静默省略。

无法确定证据针对哪个版本时，该证据不能支持正式结论。

## EV-05 每项证据只属于一个现实

每个证据记录必须引用一个且仅一个现实或观察事实，不得用一个含义模糊的证据记录同时支持多个现实。

```text
One Evidence Record -> One Reality
```

同一原始媒体或日志需要支持多个现实事实时，必须建立多个独立证据记录，并分别引用同一不可变来源及对应观察范围。

## EV-06 证据支持事实，不支持意见

证据可以支持：

```text
Observed
Measured
Recorded
```

证据不得把以下意见表述为客观事实：

```text
Looks Better
Feels Better
Seems Good
```

审美和感受属于创意评审。系统可以证明“某人作出了某项创意判断”，但不能把该判断本身伪装成客观测量事实。

## EV-07 每个正式事实都需要证据

包括但不限于以下正式事实：

```text
Selection
Verification
Publication
Replacement
Invalidation
Override
```

全部必须拥有证据。没有证据的状态变化、裁决或发布不得成为正式事实。

## EV-08 证据不得提升权威

证据可以支持事实，但不能授予或扩大权威。

即使证据表明某个提示词表现很好，提示词生成者也不会因此获得选择权威。

```text
Evidence -/-> Authority Upgrade
```

权威只能来自制度及其显式授权，不得从结果质量或证据内容反向产生。

## EV-09 证据在策略之后继续有效

策略改变未来，证据记录过去。策略被替换、失效或退役以后，其历史执行证据仍然有效。

证据属于历史和审计链，不属于临时工作流。新策略不得删除、重写或降低旧证据的可见性。

## EV-10 证据可以不足

系统必须承认正式状态：

```text
INSUFFICIENT_EVIDENCE
```

证据不足时，结论必须保持 `UNKNOWN`，不得用“可能”“大概”或模型推断补齐正式事实。

补充证据必须通过新的观察或正式记录产生，不能事后改写旧证据。

## EV-11 证据必须可复现

证据必须允许后来者重新定位当时观察的产生基础，包括：

```text
Execution
Provider
Version
Input
Output
```

可复现首先意味着能够重建证据链和观察依据。若生成过程具有随机性，也必须保留当时可获得的随机参数、模型版本和输入输出，而不能以无法完全重演为由放弃证据。

## EV-12 证据创造可审计性

证据的首要目的不是调试，而是审计。

任何正式决策都必须允许后来者重新检查：决策针对什么对象和版本、依据哪些证据、由谁在什么权威下作出、当时发生了什么。

调试日志只有满足不可变、版本绑定、现实归属和可追踪要求时，才能成为正式证据。

## EV-13 证据独立于诊断

诊断可以随着新证据改变，既有证据不得随诊断变化。

```text
Diagnosis V1: Prompt Weak
Diagnosis V2: Provider Bug
Evidence: unchanged
```

诊断只能重新引用或解释证据，不能修改证据来适配新解释。

## EV-14 证据是正式事实唯一合法基础

任何正式事实都必须同时满足：

```text
Authority
+ Evidence
+ Decision
= Formal Fact
```

缺少权威、证据或决策中的任意一项，正式事实都不得成立。

数据库记录、文件存在、模型返回成功或界面显示状态，都不能单独证明正式事实已经成立。

## 证据成立条件

证据只有同时满足以下条件才能支持正式结论：

- 引用一个明确现实或观察事实；
- 具有不可变原始内容或不可变来源引用；
- 绑定所有适用对象和版本；
- 能够定位执行、提供者、输入和输出；
- 记录产生时间和记录主体；
- 只陈述观察、测量或记录，不包含原因解释；
- 不包含权威授予或未来行动；
- 能够被后来者重新审计；
- 错误时通过追加更正处理；
- 充分性不足时明确标记，而不是补推。

## 非法状态总表

以下情况一律非法：

- 因为结论来自 AI、人或权威主体就直接信任；
- 没有证据却建立正式结论；
- 修改、覆盖、补写或删除原始证据；
- 在证据中写入原因解释；
- 证据未绑定适用版本；
- 一个证据记录同时支持多个含义不同的现实；
- 把审美意见伪装成客观证据；
- 让证据提升或扩大主体权威；
- 策略变化后删除旧证据；
- 证据不足时依靠推测建立事实；
- 无法重新定位证据对应的执行、输入和输出；
- 诊断变化时修改证据；
- 仅凭数据库记录、文件存在或接口成功宣布正式事实成立。

发现非法状态时，系统必须失败关闭并保留现有证据。

## 信任顺序

```text
Reality
  -> Evidence
  -> Expectation
  -> Gap
  -> Diagnosis
  -> Policy
  -> Execution
```

这不是时间顺序，而是信任顺序。预期定义目标，执行产生现实和观察，但任何正式推导都必须建立在证据之上。

证据是正式事实合法性的信任根；数据库只是证据和事实的存储实现，不是信任来源。

## 本章边界

本章定义正式证据和信任根，不定义知识如何升级为制度。经验、模式、知识和基础制度之间的合法推导及版本演进，已由 `IF-0007` 建立，见 [`06_Institution.md`](./06_Institution.md)。
